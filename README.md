# RoomieOS

Your shared home, organized. An ENTI 407 client-side household prototype built with Next.js, TypeScript, Tailwind CSS and Lucide.

## Local development

Use Node.js 22.12 or newer and npm:

```sh
npm ci
npm run dev
```

Open <http://localhost:3000>. The current milestone includes the responsive app shell and informative foundation screens. Household setup, profile switching and local persistence are the next milestone; this version does not initialize or modify household storage.

## Checks

```sh
npm run lint
npm run typecheck
npm test
npm run build
npm run test:browser
```

Vitest is configured for future domain/storage tests; it currently permits an empty suite. Browser tests cover navigation, responsive overflow and native-dialog keyboard behavior at 375, 768 and 1280 px. Install Playwright Chromium once with `npx playwright install chromium`, or use an existing compatible Chromium executable:

```sh
CHROMIUM_PATH=/usr/bin/chromium-browser npm run test:browser
```

The browser suite starts its own local dev server on port 3100 with an isolated `.next-e2e/` build directory, leaving a running preview on port 3000 alone. Override the test port with `ROOMIEOS_TEST_PORT` if necessary. Screenshots and failure traces are saved under the ignored `test-results/` directory.

## Hydration troubleshooting

If the development overlay shows unexpected HTML attributes such as `bis_skin_checked` or `bis_register`, a browser extension may have modified the page before React hydrated it. Those attributes are not generated by RoomieOS. Try a fresh browser profile with extensions disabled, or a private window where no extensions are allowed. If the warning disappears, disable the responsible extension for localhost and reload. See the [Next.js hydration guide](https://nextjs.org/docs/messages/react-hydration-error).

Keep hydration diagnostics enabled. The route browser test checks both uncaught errors and console errors, including React hydration warnings, in an isolated browser context. If the warning persists with extensions disabled, inspect the new diff for an application mismatch.

## Structure and deployment

- `src/app`: static App Router pages and household route-group layout.
- `src/components`: shared shell and UI primitives.
- `src/features`: feature views; foundation views will be replaced incrementally.
- `src/domain`: serializable types and, in later milestones, pure domain utilities.
- `src/state`: reserved boundary for the household provider and storage adapter.
- `src/styles`: design tokens mapped into Tailwind.

`npm run build` exports static files to `out/`, suitable for Vercel. There are no backend API routes, server mutations, remote fonts or service integrations. No deployment is performed by the foundation scripts.
